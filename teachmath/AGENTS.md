# AGENTS.md

本專案是「統計解題駕訓班」的靜態互動網站。Agent 在修改教材、互動步驟、計算器或 UI renderer 時，請優先遵守以下開發規則。

## 教學互動的核心方向

分步計算器要對齊 Photomath 的「運算步驟」顆粒度：它教使用者怎麼一步一步算出答案，而不是在同一個畫面同時講概念、考點、提醒與推導。

每個步驟畫面都應該非常窄，只處理一個當下的操作。若一個畫面需要使用者同時理解兩個以上的運算、代入、取值或整理動作，就要再拆。

## 單一步驟畫面的 UI 規則

每一步只能包含以下內容：

- 顯示當前算式，並用一種顏色標出這一步唯一會用到的數字或項目，作為輸入。
- 顯示這一步運算後產生的新數字或項目，並用另一種顏色標出，作為輸出。
- 底部只放一句操作指令，例如「取結果的最後一位數字並寫下來」。

每一步不應顯示以下內容：

- 標籤或徽章。
- 核心提示框。
- 易錯提醒框。
- 條列式概念說明卡片。
- 多段解釋、補充推導或考試意義說明。

需要講「為什麼這樣算」或「這在考試中代表什麼」時，請放在步驟流程之外的概念區、公式翻譯區、題型辨識區或錯題診斷區，不要塞進原子運算步驟。

## 拆解規則

原則：一個畫面 = 一個四則運算 / 一個取值動作 / 一個代入動作。

不可把多個運算合併到同一頁。以下情況都應拆成多個步驟：

- 同時取兩組以上數值。
- 同時計算兩個乘法或加法。
- 在同一畫面先代入、再運算、再整理答案。
- 在同一畫面把多個中間結果一起算完。

Progress dots 必須反映「總運算步驟數」，不是「總概念動作數」。步驟拆得越細，進度點也要等比例增加，讓使用者感覺每個點都代表一個實際的算式操作。

## 期望值範例的標準顆粒度

以題目 `X = 0, 1, 2`，`P(X) = 0.2, 0.5, 0.3`，求 `E(X)` 為例，不要把它做成一個「計算期望值」大步驟。應拆成類似以下 9 個獨立畫面，文案可微調，但顆粒度不可變粗：

1. 列出公式：`E(X) = Σ x·P(x)`
2. 取第一組數值：`X = 0, P(X) = 0.2`
3. 計算：`0 × 0.2 = 0`
4. 取第二組數值：`X = 1, P(X) = 0.5`
5. 計算：`1 × 0.5 = 0.5`
6. 取第三組數值：`X = 2, P(X) = 0.3`
7. 計算：`2 × 0.3 = 0.6`
8. 加總三個結果：`0 + 0.5 + 0.6`
9. 算出最終結果：`E(X) = 1.1`

## 修改互動資料時的檢查清單

新增或修改任何分步計算資料時，請檢查：

- 每個 step 是否只有一個輸入焦點。
- 每個 step 是否只產生一個新輸出。
- step instruction 是否只有一句話。
- 是否移除了步驟內的提示框、提醒框、徽章與概念卡片。
- progress dots 的數量是否等於實際 step 數。
- 使用者是否可以像 Photomath 一樣，一次只看懂一個微小操作。

## 專案實作備註

網站正式部署是純靜態 HTML/CSS/JS。正式內容位於 `index.html`、`chapters/`、`assets/`。若修改 TypeScript 來源，才需要從 `src/` 重新產生 `assets/js/`。

預覽時請用靜態伺服器開啟，不要直接用 `file://` 開 HTML，因為互動程式使用瀏覽器 ES modules。
